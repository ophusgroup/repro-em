# Plotting

Plotting an image or chart is fine, as long as it links back to the raw experimental data.

A figure is the most compressed form of a result, and the only form most readers will ever see. It is worth treating with the same care as the data.

## Figures as derived data

A figure is a data product, produced by code, from an input. Treat it that way: every published figure should be generated by a script that takes the archived data and emits the file, with no manual steps in between.

Manual steps are where results go wrong. Cropping in an image editor, adjusting levels by eye, and pasting panels together by hand all leave no record, cannot be checked, and cannot be redone when a reviewer asks for a different scaling. If a figure cannot be regenerated by running one command, the link back to the data is already broken.

This also solves a practical problem. Reviewers ask for changes, and a scripted figure can be regenerated in seconds with the numbers guaranteed to still match the data.

## Colormaps and scaling

Use a perceptually uniform colormap. The rainbow and jet maps introduce visual features that are not in the data, hide features that are, and are unreadable to colorblind readers ([Crameri et al., *Nat. Commun.* 2020](https://doi.org/10.1038/s41467-020-19160-7)).

Match the map to the data. Sequential data takes a sequential map. Data with a meaningful zero, such as DPC, strain, or a difference image, takes a diverging map centered on zero. Orientation and phase are cyclic and need a cyclic map, or the discontinuity will read as a physical boundary.

State the scaling. Intensity limits, whether the scale is linear or logarithmic, and any gamma applied. Clipping the display range is a normal and useful thing to do, and it becomes misleading only when it goes unstated. The same holds for smoothing and denoising: if a filter was applied before display, say which one and with what parameters, and show the unfiltered data somewhere.

## What a figure must disclose

Every figure should carry, in the caption or the metadata:

- A scale bar, with the calibration it came from
- Modality and the key acquisition parameters, including dose
- Colormap and intensity range
- Any filtering, smoothing, or background subtraction applied before display
- Whether the data shown is one field of view or an average, and over how many
- An identifier resolving to the archived dataset and the code that made the figure

The last one is the one that matters. Every other item can be reconstructed by a reader who has the data and the script.

The phrase "representative micrograph" deserves particular scrutiny. It usually means one image was chosen from many, by a person, using criteria that were never written down. If the full set is published, the reader can judge what representative meant. See [publishing](publishing.md) and [chain of custody](chain-of-custody.md).
