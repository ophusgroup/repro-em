# Reproducibility framework

## FAIR data

Findable, accessible, interoperable, reusable. The FAIR guiding principles ([Wilkinson et al., *Sci. Data* 2016](https://doi.org/10.1038/sdata.2016.18)) set out what published research data has to satisfy to be useful to anyone other than the group that recorded it.

:class: rpe-light-only
:alt: The FAIR data principles

:::

Measured against those principles, most materials TEM data currently fails all four.

| | FAIR asks for | materials TEM today |
|---|---|---|
| findable | a persistent identifier and rich metadata | usually no identifier at all |
| accessible | retrievable over an open protocol | "available upon reasonable request" |
| interoperable | an open, documented format | proprietary and reverse engineered |
| reusable | calibrations, license, and provenance | a figure in a PDF |

Two points about FAIR are worth stating plainly, because both are commonly misread.

FAIR is not the same as open. Accessible means retrievable under clearly stated conditions, which can include authentication, embargo, or restriction. Industrial data under embargo can be fully FAIR, provided the metadata is public and the terms are explicit. See [objections and exceptions](objections.md).

FAIR is written for machines as much as for people. The requirement is that software can find, fetch, and interpret a dataset without a human in the loop, which is why an open self-describing container and a documented axis order are requirements rather than preferences.

These principles are also already written into the data management plans that most funding agencies require, so this is an existing obligation rather than a new one.

## The chain of custody

The pages that follow work through the framework in the order the data moves, from the detector to the published figure.

1. **Detector output**, signed at the instrument. See [validated detectors](framework/detectors.md).
2. **Raw data**, immutable, hashed, stored with its metadata. See [data](framework/data.md) and [file formats](framework/formats.md).
3. **Calibration**, recorded with a value, method, uncertainty, and date. See [metadata](framework/metadata.md).
4. **Reconstruction**, with its code, parameters, and random seed. See [computational imaging](framework/computational-imaging.md).
5. **Analysis**, open source, in a pinned environment. See [analysis and plotting](framework/analysis.md).
6. **Figure**, generated by a script that resolves back to the data. See [chain of custody](framework/chain-of-custody.md).

Every step records the hash of its inputs, so a published figure can be traced back to signed detector output. Validation then applies across the whole chain rather than to any single link, which is what [benchmarks](framework/benchmarks.md) covers.
